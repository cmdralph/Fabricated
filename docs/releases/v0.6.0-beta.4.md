# Fabricated v0.6.0-beta.4

> **Beta.** Fabricated runs Fabric mods on NeoForge and Forge. Many Fabric mods work; some still don't. Back up your
> worlds.

The fourth beta adds Minecraft 1.19.2 on Forge 43, in beta, and fixes Fabric mods that crashed a server or a client,
lost a hook or kept a client from exiting. When a crash involves a Fabric mod, the log and the crash report now name
it. It covers NeoForge (1.21.1, 1.21.11, 26.1.2, 26.2, 26.3), Forge 52 and 61 to 66 (1.21.1, 1.21.11, 26.1.2, 26.2,
26.3), Forge 47 (1.20.1) and, new, Forge 43 (1.19.2).

## What changed on every platform

- **OneConfig 1.8.0's UI works on NeoForge** (PKG-6); on Forge the test mod checks the same case.
- **A crash names the Fabric mod it involves.** When the game stops on an error a Fabric mod is involved in,
  Fabricated writes a diagnostics block in `logs/latest.log` and at the start of the crash report's details: the mod's
  name, id, version and jar, the mixin that failed and the class it was applied to (or the mod's class in the stack
  trace), the loader and the versions, and what Fabricated does about it. It names a mod only where that is certain.
  See [*Troubleshooting: the diagnostics block*](https://github.com/cmdralph/Fabricated/blob/main/docs/COMPATIBILITY.md#troubleshooting-the-diagnostics-block).
- **On Forge too, a mixin that fails as Mixin applies it is left out from the next launch** (APPLY-3), as on
  NeoForge, where it stopped every launch the same way. On NeoForge 1.21.11 to 26.3 so is one that fails as a
  dedicated server starts (APPLY-4). It is tried again once the mod's jar, Fabricated, Minecraft or the loader changes,
  or once `.fabricated/mixin-failures.json` is deleted.
- **Vanilla's checks put back in crop growth and shovels** (SEAM-12, SEAM-13). Where the platforms ask a soil's or a
  block's own extensions in place of vanilla's checks, vanilla's checks go back for the blocks keeping the platforms'
  defaults; a NeoForge or Forge mod's block answering them itself works as before. Balm's custom farmland (NeoForge and
  Forge) and Farmer's Delight Refabricated's rich soil (NeoForge 1.21.1 and 1.21.11) speed crops up as on Fabric, and
  FrozenLib's shovel behaviours, which Wilder Wild's blocks use, run on NeoForge 1.21.1 to 26.2 and Forge 43 to 65.
- **Supplementaries' lit lumisene no longer stops the server** (LEAVE-6: NeoForge 1.21.1, Forge 47 and 52). It sets
  the blocks around it alight through vanilla's fire spread method, which the platforms gave the side the fire comes
  from, and the call failed once lumisene burnt them. A Fabric mod's invoker of a vanilla method the platform gave a
  parameter its own code ignores now calls the platform's method with a fixed value. What differs from vanilla's fire
  is under *Known limits* below.
- **Screen hooks apply where the platforms hand the screen its input their own way** (LAMBDA-14): owo-lib's, JEI's,
  ReplayMod's and Architectury's key, character and mouse hooks, per platform below. Essential's draw screen event
  hooks apply on NeoForge and Forge 47 to 64 (SCREEN-3; not yet checked in a game).
- **A truer report.** A `@Pseudo` mixin whose target is missing, where what the target belongs to is installed
  (Minecraft, Fabric API, a package an installed jar holds), gets one INFO line saying Mixin skips it (PRE-37:
  Polymer's mixins of Fabric's registry sync on NeoForge). More known limits are named next to the hooks they leave
  out, with what doesn't work and what to do: the new ones below, and documented ones it listed without a reason
  (LIMIT-3): Additional Entity Attributes' water speed on every platform, Reach Entity Attributes and Porting Lib on
  Forge 47, Ledger's campfire logging, and OneConfig's key mapping accessor on NeoForge. Where vanilla's methods aren't
  put back because a NeoForge or Forge mod's mixin hooks the platform's code, the line names the method it hooks.
- **Safer translation** (SEC-12): remapping a Fabric jar's strings no longer takes time growing with the square of a
  long run of letters, and a string of a few thousand path segments no longer overflows the stack.
- **A hook of a call in a method the platform reduced to an overload's call** no longer stops the game as Mixin applies
  it (OVERLOAD-5: a redirect or wrapper of a call whose arguments end with its method's parameters). No mod is known to
  have hit it.
- **Bugs are reported with a form:**
  [opening an issue](https://github.com/cmdralph/Fabricated/issues/new?template=bug_report.yml) asks for the loader and
  the versions, the mod list, `logs/fabric-bridge-report.txt` and the log.

## NeoForge

- **1.21.1:** owo-lib's braid layers get typed characters and ReplayMod's character hooks apply (LAMBDA-14);
  Supplementaries' lit lumisene no longer stops the server (LEAVE-6).
- **1.21.11 to 26.3:** REI's Fabric build shows the mods' recipes where it reads recipes from the data packs because
  the server sends none, and the internal packs Puzzles Lib's mods hide are no longer in the pack screens
  (PROVIDER-23).
- **26.x:** Artifacts' underwater mining speed and FrozenLib's air bubbles apply: vanilla's check for water at an
  entity's eyes goes back in the mining speed and the HUD's air bubbles wherever it answers as NeoForge's check does
  (SEAM-9). The report no longer lists the enum constants Farmer's Delight Refabricated and Flashback add as missing
  (ENUM-10).

## Forge 52 and 61 to 66 (Minecraft 1.21.1, 1.21.11 and 26.x)

- **Forge 52 (1.21.1) now builds from the `forge` branch**, beside Forge 61 to 66, and `forge-legacy` holds Forge 43
  and 47. Nothing changes about which jar to download: Forge 1.21.1's is still
  `fabricated-forge-<version>+mc1.21.1.jar`, for Forge 52 or later.
- **Forge 52:** Farmer's Delight Refabricated loads on clients, where it was disabled with its add-ons (ENUM-9); Fabric
  API's custom ingredients can be written as JSON, so Supplementaries' dynamic sign post recipes are generated
  (CORPUS-115); owo-lib's braid layers get typed characters and JEI's character hooks apply (LAMBDA-14);
  Supplementaries' lit lumisene no longer stops the server (LEAVE-6).
- **Forge 52 and 61 to 66:** a Fabric mod's own ingredient is written as JSON as on Fabric, where Forge's codec threw
  and a mod writing such a recipe lost it (CORPUS-115).
- **Forge 61 to 66:** with Iris's Fabric build and a shader pack casting shadows, a Forge 61 or 64 client no longer
  crashes in its first frame in the world (LEAVE-5); Inventory Profiles Next's mob bucket accessor applies, as on
  Forge 47 and 52 (LEAVE-5); Architectury's screen click and release events fire (LAMBDA-14); SpruceUI's screen render
  events apply on Forge 64 (SCREEN-3: LambDynamicLights). A Forge 65 or 66 client with Forge Config API Port's Fabric
  build, or any Fabric mod watching a file with night-config's default file watcher, exits as it closes, where it
  wrote a crash report and exited 15 seconds later (CORPUS-116).

## Forge 43 (Minecraft 1.19.2), new, in beta

- **The first release for 1.19.2:** `fabricated-forge-0.6.0-beta.4+mc1.19.2.jar`, for Forge 43 (CI tests 43.5.2) on
  Java 17, with Fabric API 0.77.0, the last for 1.19.2. Fabricated ships natively the same seven Fabric API modules as
  on Forge 47 (base, biome, dimensions, key bindings, loot v2, loot tables, particles), and puts back what Forge 43
  changes where Fabric mods rely on it: a Fabric mod's registration into vanilla's registries, Fabric API's resource
  loader and its mods' packs, its object builder on clients (and every Fabric mod needing it), flammable blocks,
  point-of-interest blocks, tooltip components, the HUD callback, and a new world leaving a mod's optional built-in
  data packs off.
- **Fabric's renderer API** is bridged as on Forge 47: Fabric block models in chunk sections, alone and inside vanilla's
  multipart and weighted models, as falling blocks, moved by pistons and with the breaking overlay, and Fabric item
  models; a model that throws fails alone.
- **Sodium and Iris for 1.19.2:** Sodium 0.4.4 with Indium 1.0.9, and Iris 1.6.11 with them, the last Fabric builds for
  1.19.2, reach their world. Sodium's copy of JOML, which 1.19.2 doesn't ship, stays Sodium's (PLAT-8), and Fabric mods'
  names for the members of the rendering classes Minecraft ships unobfuscated are remapped, so Iris loads (PLAIN-2).
  CI runs them without a shader pack, as informational runs. Iris's block and fluid hooks in the chunk section
  rebuild, where Forge calls its own overloads, and those of its separate ambient occlusion are left out, the report
  naming them.
- **What doesn't work there yet** is in the support matrix's Forge 1.19.2 column: Fabric API 0.77 has no model loading
  plugins or Fabric model formats, and its `fabric-models-v0` loads without a CI check covering it (note 23); the
  corpus runs of popular Fabric mods haven't run on Forge 43 yet, so how they fare there is unknown (note 24); and the
  hooks left out on Forge 47 are left out on Forge 43 too, where Forge's code is the same
  ([*Unsupported on Forge*](https://github.com/cmdralph/Fabricated/blob/main/docs/COMPATIBILITY.md#unsupported-on-forge)).
  Modrinth has no Flashback for 1.19.2.

## Support matrix

The other loaders, Minecraft versions and tested builds are those of v0.6.0-beta.3, all beta. The matrix gains a
column, Forge 1.19.2 (beta), and a row: a mixin that failed as Mixin applied it is left out from the next launch, and
the diagnostics block, on every loader and version. See the
[support matrix](https://github.com/cmdralph/Fabricated/blob/main/docs/COMPATIBILITY.md#support-matrix).

## Upgrading from v0.6.0-beta.3

- **Remove the old jar**; two Fabricated jars in `mods` are refused.
- **The first launch translates every mod again**, once, automatically: the translation cache is rebuilt.
- **`config/fabricated.json` carries over:** no setting changed. The developer API is still 1.1.

## Known limits, new in this release's notes

- **Plant survival and stems** (SEAM-12). Where the platforms ask the soil's `canSustainPlant` in place of vanilla's
  soil check for a cactus (Forge 47, 52 and 61), mushrooms (Forge 52 and 61) or a stem's fruit (NeoForge 1.21.1 and
  1.21.11, Forge 61), hooks of vanilla's check are left out: Farmer's Delight Refabricated's rich soil doesn't take
  them through its hooks. On Forge, a stem's and the pitcher crop's growth stays Forge's, so a hook of the farmland
  check doesn't run for them. The report names both.
- **Other fluid checks and fluid pushing** (SEAM-9; NeoForge, Forge 47 to 66). The platforms ask their fluid types
  where vanilla asks for water or lava, and push entities through fluids in code of their own, so Lithium's fluid
  pushing caches, Wilder Wild's mesoglea, FrozenLib's water-like fluids, Expandability's swimming events and, on
  Forge 47, Milk Lib's effect clearing are left out; with a mod's fluid alone at an entity's eyes, NeoForge 26.x's own
  check runs without the hooks. On Forge 64 to 66, Fabric API's own hooks of a living entity's breathing, swimming
  and fluid jumping and a boat's floating, for its custom fluids, are left out too: a Fabric fluid doesn't drown, carry
  or lift entities there. The report names them.
- **Fire set through a Fabric mod's invoker** (LEAVE-6: Supplementaries' lit lumisene). The call runs the platform's
  fire spread, not vanilla's. A NeoForge or Forge mod's block that overrides the flammability or caught-fire extension
  is asked for a fixed side (the west), whatever side the mod meant; blocks keeping the defaults ignore the side. TNT
  goes off before the burnt block is replaced (after it on Forge 43, as in vanilla), how likely a block is to catch is
  the platform's flammability (it differs only for a mod's fire block with odds of its own), and Forge 43 and 47 use
  the fire's chance where vanilla uses its age.
- **Hoppers' containers** (SEAM-14). On NeoForge 1.21.11 to 26.3 hoppers move items to and from the containers
  FrozenLib's hopper API keeps them from; on Forge 47 Lithium's hopper ejection optimisation is left out.
- **The HUD and screens the platforms draw their own way** (HUD-8, LAMBDA-14, SCREEN-3), each named in the report:
  - NeoForge's HUD layers: Farmer's Delight Refabricated's comfort and nourishment overlays (1.21.11 to 26.3),
    Artifacts' hotbar hooks (1.21.11, 26.1.2), GlitchCore's vehicle hearts, air and frozen overlay hooks (every
    version), Apoli's air bubble sprites and Puzzles Lib's HUD events (1.21.1), and Do a Barrel Roll's (1.21.1,
    1.21.11);
  - Forge 52's screen mouse input: owo-lib's braid layers get no key modifiers with a click or a release, and
    Architectury's mouse drag event doesn't fire for screens;
  - the Controls screen's reset of every key (NeoForge and Forge): JEI's Fabric build doesn't reset its own key
    modifiers;
  - Forge 61 to 66's item tooltips in container screens: ShulkerBoxTooltip's container previews;
  - NeoForge 1.21.1's title screen: FancyMenu's condition on the version text doesn't apply.
- **Ledger's campfire logging** (LOCAL-6) is still open, and holds on every version Ledger runs on (NeoForge 1.21.1 to
  26.3, Forge 52 to 66): an item put on a campfire isn't logged. The report names it. Its logging of the fire an
  explosion starts works.

The limits of v0.6.0-beta.3's notes still hold, except Supplementaries' lumisene on Forge 47, fixed here (LEAVE-6). All
limits are in [`docs/COMPATIBILITY.md`](https://github.com/cmdralph/Fabricated/blob/main/docs/COMPATIBILITY.md);
details of every change are in
[`docs/CHANGELOG.md`](https://github.com/cmdralph/Fabricated/blob/main/docs/CHANGELOG.md).

## Installing

1. Install NeoForge or Forge for your exact Minecraft version (Forge 43 for 1.19.2).
2. Download the jar for your loader and Minecraft version, from this release or from CurseForge:
   - NeoForge (1.21.1, 1.21.11, 26.1.2, 26.2, 26.3): `fabricated-neoforge-0.6.0-beta.4+mc<minecraft>.jar`.
   - Forge (1.19.2, 1.20.1, 1.21.1, 1.21.11, 26.1.2, 26.2, 26.3): `fabricated-forge-0.6.0-beta.4+mc<minecraft>.jar`.
3. Check the jar against `SHA256SUMS.txt`.
4. Put the jar in `mods`, next to your Fabric mods and the official Fabric API jar for that version (0.77.0 for
   1.19.2). Remove Sinytra Connector and any older Fabricated jar.

Fabricated never downloads anything and never modifies your mod jars. `logs/fabric-bridge-report.txt` says what loaded
and why anything didn't. If you hit a crash, please open an issue with the
[bug report form](https://github.com/cmdralph/Fabricated/issues/new?template=bug_report.yml) and attach
`logs/latest.log` (or the crash report) and that report.
