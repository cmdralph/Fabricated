# Fabricated v0.4.0-alpha

> **Pre-release.** Fabricated is in early alpha and not ready for production. Builds are stable in CI, but many Fabric
> mods still won't run. Use these builds at your own risk, and back up your worlds.

The jars now carry their real version (`0.4.0`). The v0.3.0-alpha jars were still named `0.1.0`.

## Highlights

- **Fabric's renderer API runs on NeoForge on all four versions.** Fabric block models are drawn in the world, on
  moving blocks (pistons, falling blocks), in the breaking overlay, and inside vanilla multipart and weighted models.
  Fabric's model formats load through NeoForge's model parsers. `fabric-model-loading-api-v1`, which v0.3.0-alpha
  turned off on the client, now loads on every version.
- **Sodium and Iris for NeoForge draw Fabric block models.** On 26.x they use Sodium's own Fabric renderer. On 1.21.11,
  Sodium meshes parts made from the model's quads. The *Fabric* builds of Sodium and Iris are still refused by
  default: use their NeoForge builds.
- **Many more mods with deep hooks load.** When NeoForge's code can't take one of a mod's hooks, mixin pre-flight now
  leaves out just that hook and loads the mod, where it used to disable the whole mod. The report names every hook it
  left out. Dozens of generic repairs re-point hooks at code that NeoForge renumbered, moved or changed.
- **26.3 is stable** on NeoForge 26.3.0.95 and is no longer best-effort.
- **New: experimental Forge builds** for 1.21.11 (Forge 61), 26.1.2 (Forge 64), 26.2 (Forge 65), 26.3 (Forge 66) and
  1.20.1 (Forge 47). These are server-side previews. See [Forge builds](#forge-builds-experimental).

## What's new on NeoForge

### Rendering

- **Fabric renderer API:**
  - Indigo and the renderer API load on every version.
  - Fabric models get NeoForge's level-aware defaults: the level, model data, ambient occlusion, and baked colours and
    normals.
  - A glowing moving block has its outline on 26.2 and 26.3.
- **Picture-in-picture renderers** registered with Fabric are used on 26.2 and 26.3.
- **Fluid tints on 1.21.11:** a Fabric fluid render handler's colour now tints fluids that NeoForge's renderer draws.

### Fabric API

- **Biomes:** `fabric-biome-api-v1` is native on all four versions. Biome changes go through NeoForge's biome
  modifiers.
- **Fluids:** Fabric mods' fluids get NeoForge fluid types. Before, NeoForge crashed with "Mod fluids must override
  getFluidType".
- **Storages:** Fabric storages inside items and NeoForge's item capabilities see each other, both ways.
- **Energy:** when a Fabric mod brings Team Reborn's energy library, Fabricated bridges its energy with NeoForge's.
- **Disconnect events:** Fabric's configuration-phase `DISCONNECT` events fire on the server and the client.
- **Client modules:** CI now gates the Fabric API client modules most client mods use, on 26.x: key mappings, HUD
  elements, screen events and client commands.
- **Mod entrypoints:**
  - Main entrypoints run where Fabric runs them on 26.x clients.
  - Language adapters are created before any mod's mixin plugin loads, as on Fabric.
  - Mods that add entrypoints through Fabric Loader's internal entrypoint storage, as FrozenLib does, are supported.

### Mod integrations

- **Plugins:** a Fabric mod's plugins for JEI, REI, Jade, WTHIT and Simple Voice Chat are found by those mods'
  NeoForge builds. CI checks that each host calls the test mod's plugin. EMI plugins are converted too, but are
  untested: EMI has no NeoForge build for these versions.
- **Custom values:** a Fabric mod's custom values reach NeoForge mods that read them, for example Sodium's and
  Lithium's option overrides.

### Loader and mixins

Pre-flight and translation now handle many more patterns:

- Lambdas and anonymous classes that NeoForge's patches renumber.
- Injection points that moved into NeoForge's own hooks.
- Captured values and locals, which pre-flight now tells apart.
- Constructors that NeoForge extended.
- Enum mixins, which become NeoForge enum extensions.
- Duck mixins into library classes such as Brigadier, which become static bridges.
- Split packages, which are merged into one module.
- Nested jars' mixin configs and native libraries.
- Methods the platform made `final`.
- A mixin's private method that would hide a default method the platform added.

### Networking

- Fabric's packet context is filled in and bound.
- Payload types registered late are accepted.
- Payloads that have no NeoForge registration are sent. Polymer's handshake needs this.

### Security and robustness

- **Untrusted jars:** a review of untrusted-input handling fixed several ways a crafted jar could disable every
  Fabric mod (SEC-1 to SEC-4).
- **Cache:** fixes for cache keys and stale entries.

Details for every item are in [`docs/CHANGELOG.md`](../CHANGELOG.md), and per-module status is in
[`docs/COMPATIBILITY.md`](../COMPATIBILITY.md).

## Forge builds (experimental)

Fabricated now builds for Minecraft Forge from two branches:

- **`forge`:** Forge 61, 64, 65 and 66, for 1.21.11, 26.1.2, 26.2 and 26.3.
- **`forge-legacy`:** Forge 47.4, for 1.20.1, with Fabric API 0.92.12.

**What CI checks** (dedicated servers only):

- A Fabric mod is discovered and translated. On 1.20.1 it is remapped from Intermediary to the SRG names that Forge
  47 runs.
- Its main and server entrypoints run, with the registries open.
- Its mixins, access wideners and injected interfaces are applied.

**With the official Fabric API jar,** the server starts on all five Forge versions and no Fabric API module is turned
off.

**Native on Forge:**

- `fabric-api-base`.
- Fabric's loot events: `fabric-loot-api-v3`, and on 1.20.1 `fabric-loot-api-v2` and `fabric-loot-tables-v1`.
- On 1.20.1: `fabric-biome-api-v1` and `fabric-dimensions-v1`.

**Bridged on Forge:**

- Tag files' `fabric:remove` entries.
- Fluid types for Fabric fluids.
- Default attribute changes, on Forge 64 to 66.
- Advancement events, on Forge 66.

**Limits:**

- **No client support yet.** Fabric mods' client entrypoints don't run on Forge, and CI doesn't start a Forge client
  at all.
- **Partly informational CI.** The Forge 61 to 66 server runs are informational. The Forge 47 server run is a gate.
- **Not for players yet.** Use these builds only for testing.

## Known limits (NeoForge)

- **Login queries** (`ServerLoginNetworking`, `ClientLoginNetworking`) aren't supported, because NeoForge has no hook
  for that phase.
- **Renderer mods:** the Fabric builds of Sodium and Iris are refused by default. Use their NeoForge builds.
- **Picture-in-picture renderers** registered with Fabric aren't used on 1.21.11 and 26.1.2.
- **Debug options screen:** it keeps vanilla's sorting and search.
- **Multiplayer:** CI tests dedicated servers and singleplayer clients, but not a client joining a dedicated server.
- **Private fields:** fields NeoForge requires to stay private, such as `Biome.climateSettings`, are never widened.
  The report lists every mod that asks for one.

## Installing

1. Install NeoForge (or, for testing, Forge) for your exact Minecraft version.
2. Download the jar for that version:
   - NeoForge: `fabricated-0.4.0+mc<minecraft>.jar`.
   - Forge: `fabricated-forge-0.4.0+mc<minecraft>.jar`.
3. Check the jar against `SHA256SUMS.txt`.
4. Put the jar in `mods`, next to your Fabric mods and the official Fabric API jar for that version.

Fabricated never downloads anything and never modifies your mod jars. `logs/fabric-bridge-report.txt` says what loaded
and why anything didn't.

If you hit a crash, please open an issue and attach `logs/latest.log` and `logs/fabric-bridge-report.txt`.
