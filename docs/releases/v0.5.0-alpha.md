# Fabricated v0.5.0-alpha

> **Pre-release.** Fabricated is in early alpha and not ready for production. Builds are stable in CI, but many Fabric
> mods still won't run. Use these builds at your own risk, and back up your worlds.

## Highlights

- **New: Minecraft 1.21.1 on NeoForge 21.1.** It is a full target, like the other NeoForge versions:
  - servers and clients, with and without the official Fabric API jar (0.116.17);
  - 18 native Fabric API modules, including `fabric-particles-v1`;
  - the storage and energy bridges on NeoForge 21.1's handler capabilities;
  - the same CI checks as every other version.

  Fabric mods for 1.21.1 use Intermediary names, so they are remapped to Mojang's names on first load, as on 1.21.11.
- **The Forge builds run Fabric mods' client side.** Fabric mods' client entrypoints now run on Forge 61 to 66 and
  Forge 47, and CI starts a Forge client on all five versions. With the official Fabric API jar, Forge clients reach a
  world. The Forge builds are still **experimental**: see [Forge builds](#forge-builds-experimental).
- **Fabric mods that build content early, or depend on each other, load in the right order on every platform:**
  - content built before the main entrypoints waits for them;
  - the built-in registries freeze after the main entrypoints, as on Fabric;
  - Fabric mods that depend on each other, in pairs or rings, no longer stop the loader's mod sorting.
- **Cleanup:** the mixin pre-flight's repairs are split into classes by kind, behind one ordered table. About 3,700
  lines of duplicated per-version code are merged into shared folders. Behaviour is unchanged.

## What's new on NeoForge

- **1.21.1:** see Highlights. Its Fabric renderer API loads, but Fabric models with their own block quads aren't
  drawn in chunk sections yet (FRAPI-5). Fixed from the 1.21.1 mod corpus before the release:
  - `FabricBlockSettings.create()` and the `build()` Fabric adds to vanilla's block entity type builder (CORPUS-39,
    CORPUS-40);
  - entity data serializers that Fabric mods register through vanilla's method, which NeoForge 21.1 refuses
    (CORPUS-41);
  - Fabric mods shading a library NeoForge 21.1 already ships (CORPUS-43).
- **A Fabric mod whose initializer fails** no longer stops the game through content it had built but not registered
  (CORPUS-42): that content is dropped, with an error naming it.
- **Early content and registries** (CORPUS-31, CORPUS-32): mods like BetterNether and BetterEnd create their content
  before their main entrypoints run. That content is now registered once the entrypoints have run, and the built-in
  registries freeze only after that.
- **Mods that depend on each other** (ORDER-1): Fabric allows two or more mods to depend on each other, but
  NeoForge's and Forge's mod sorting stopped the game at such a cycle ("Mod Sorting failed"). Fabricated now drops
  only the orderings inside a cycle, so the mods load.
- **CI:**
  - A quick check runs on each push.
  - The full matrix runs on every pull request.
  - The extended runs (the mod corpora and other mods' builds) run by hand and on release tags.

## Forge builds (experimental)

The Forge builds remain **experimental previews**: use them for testing, not for playing. They come from two branches:

- **`forge`:** Forge 61, 64, 65 and 66, for 1.21.11, 26.1.2, 26.2 and 26.3.
- **`forge-legacy`:** Forge 47, for 1.20.1, with Fabric API 0.92.12.

**New since v0.4.0-alpha:**

- **Client side:**
  - Fabric mods' client entrypoints run, right after the main ones, with the registries open.
  - CI starts a client on every Forge version, as a gate.
  - With the official Fabric API jar, the client reaches a world.
- **Server runs:** both server runs on every Forge version are now gates, including the one with Fabric API.
- **Checked on every Forge version, with the official Fabric API jar:**
  - networking: a packet round trip with the integrated server;
  - commands;
  - block break events and bed events;
  - the use and attack callbacks.
- **Storages:** Fabric mods' item and fluid storages and Forge mods' item and fluid handlers see each other, on blocks
  and for fluids in items.
- **Rendering:**
  - `fabric-rendering-v1` loads on Forge clients. Fabric's colour providers are read from Forge's maps.
  - On Forge 47: Fabric particles, model modifiers before baking, and screen mouse and key events.
  - On Forge 61: the block dust tint event.
- **Damage and sleep events:**
  - The after-damage event fires on Forge 61 and 64, with the damage actually dealt.
  - Forge 47 asks Fabric's daytime-sleep event.
- **Corpus runs reach the game:** the Forge corpus runs reach the game, with 85 to 151 Fabric mods loading. Before,
  Forge loaded only itself. This needed:
  - Forge's own loading errors to show instead of Fabricated's crash (LOADERR-1);
  - no duplicate nested jars (JIJ-1);
  - MixinExtras for Fabric mods on Forge 61 to 66 (MIXEXT-3);
  - Forge Config API Port's Fabric build loading (REPL-1).

**Limits on Forge:**

- **Some corpus mods still stop the game.** On the Forge 65 and 66 clients, some mods' `@Local` hooks stop the game
  (PRE-18). Forge 61 to 66 retyped a field that Fabric's biome feature modifications write (CORPUS-33).
- **Fabric API is mostly passed through.** Fabricated ships only a few Fabric API modules natively on Forge; the rest
  load from the official Fabric API jar.
- **Not for players yet.** Use these builds only for testing.

## Known limits (NeoForge)

- **Login queries** (`ServerLoginNetworking`, `ClientLoginNetworking`) aren't supported, because NeoForge has no hook
  for that phase.
- **Renderer mods:** the Fabric builds of Sodium and Iris are refused by default. Use their NeoForge builds.
- **Fabric renderer API on 1.21.1:** Fabric models with their own block quads aren't drawn in chunk sections yet
  (FRAPI-5).
- **Some popular mods still stop 1.21.1:**
  - Moonlight (and the mods needing it): it uses an internal class of Fabric API's resource loader that Fabricated
    doesn't provide (CORPUS-44);
  - LambDynamicLights on the client (CORPUS-45);
  - some mods of the advanced test corpus (CORPUS-46).
- **Picture-in-picture renderers** registered with Fabric aren't used on 1.21.11 and 26.1.2.
- **malilib** (and MiniHUD, Tweakeroo and Litematica) is refused until a CI run verifies it on the map Fabricated now
  restores for it.
- **Multiplayer:** CI tests dedicated servers and singleplayer clients, but not a client joining a dedicated server.

## Installing

1. Install NeoForge (or, for testing, Forge) for your exact Minecraft version.
2. Download the jar for that version:
   - NeoForge: `fabricated-0.5.0+mc<minecraft>.jar`.
   - Forge: `fabricated-forge-0.5.0+mc<minecraft>.jar`.
3. Check the jar against `SHA256SUMS.txt`.
4. Put the jar in `mods`, next to your Fabric mods and the official Fabric API jar for that version.

Fabricated never downloads anything and never modifies your mod jars. `logs/fabric-bridge-report.txt` says what loaded
and why anything didn't.

If you hit a crash, please open an issue and attach `logs/latest.log` and `logs/fabric-bridge-report.txt`.
