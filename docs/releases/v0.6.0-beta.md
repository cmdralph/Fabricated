# Fabricated v0.6.0-beta

> **Beta.** Fabricated runs Fabric mods on NeoForge and Forge. This is its first beta: every platform and Minecraft
> version below is held to the same bar in CI, and what a platform can't do is listed as unsupported, with the
> reason. Many Fabric mods work; some still don't. Back up your worlds.

Fabricated leaves alpha on all three platforms: NeoForge (1.21.1, 1.21.11, 26.1.2, 26.2, 26.3), Forge 61 to 66
(1.21.11, 26.1.2, 26.2, 26.3) and Forge 47 (1.20.1). The Forge builds are no longer experimental.

## What beta means

On every platform and version, CI checks that:

- **Fabricated stops no launch.** The only launches it stops are its refusals (Sinytra Connector and a second
  Fabricated jar everywhere; on Forge, a jar with its own copy of Fabric Loader too), each with one error naming the
  jars. A Fabric mod that fails is that
  mod's: it is disabled, or marked failed while the game goes on, and `logs/fabric-bridge-report.txt` says why.
- **No known crash or silent failure of a supported feature is open** (no P0 or P1 finding).
- **Untrusted jars stay bounded.** Every jar, nested ones included, goes through the archive checks, and the jars
  nested in your mods are limited per mod and, new in this release, per launch.
- **Upgrading doesn't break a game directory** (see *Upgrading*), and the developer API (`docs/API.md`, 1.1) is
  stable.

## Highlights

- **Sodium, Iris, Essential, malilib (with MiniHUD, Tweakeroo and Litematica) and Flashback run from their Fabric
  builds**, on NeoForge and Forge, each a CI gate on every version it has a build for. Their refusals are lifted.
  Essential's loader downloads Essential in the first launch, and Essential loads from the next. Flashback has no
  Forge 47 build.
- **Fabric's renderer API works on every platform.** Fabric block models are drawn in chunk sections, as moving blocks
  (falling, pushed by a piston), with the breaking overlay, as items (hotbar, hand, dropped, item frames) and as blocks
  drawn as entities (a minecart's contents; on 1.21.1 and 1.20.1 from vanilla's quads, as upstream draws them). Fabric API's own renderer (Indigo) draws them, or Sodium's or
  Forgified Fabric API's when installed. A Fabric model that throws while it is drawn no longer crashes the game: the
  platform draws that block from then on, and the log and the report name the model once.
- **Faster cached launches.** A launch with everything already translated reads 1.21.x's mapping table only when
  something needs it, no longer re-reads and hashes the in-game mod, and checks archive entry names in one pass: on 1.21.x discovery with Fabric API went from 471 to
  554 ms to 406 to 492 ms. The report's new *Launch timings* section shows where a launch spends its time.

## What changed on NeoForge

- **More of CI is a gate:** the client with Fabric API, Sodium for NeoForge on 1.21.11 and with a shader pack on 26.x,
  the Fabric builds of Sodium and Iris with a shader pack, Continuity, Sodium Extra and Reese's Sodium Options (26.1.2
  and 26.2), OneConfig and PolyPlus, and the clients with Forgified Fabric API (1.21.1's with Sodium for NeoForge, and
  its renderer on 1.21.1, 26.1.2 and 26.2). Each held on two extended runs before this release.
- **Mods that stopped 1.21.1 in v0.5.1 load:** Moonlight (CORPUS-44), LambDynamicLights on the client (CORPUS-45) and
  Pehkui (CORPUS-46). Fabric's load conditions apply in 1.21.1's JSON data loaders (CORPUS-49), Fabric key bindings
  are native on 1.21.1 (KEYMAP-2), and on 1.21.11 a Fabric mod registering an entity data serializer no longer stops
  the game (SER-1).
- **A mixin that pre-flight passes but fails as Mixin applies it** is left out from the next launch, and its mod loads
  without it (APPLY-1); the report says which.
- **Rendering:** Fabric models in 1.21.1's chunk sections (FRAPI-5), blocks drawn as entities on 26.x (FRAPI-6),
  Fabric HUD elements attached to a vanilla one keep vanilla's conditions (HUD-3), and 1.21.1's model modifiers reach a
  multipart model's parts (MODEL-4).
- **With Forgified Fabric API:** a Fabric mod's own command argument types work on the client (PROVIDER-12: on
  1.21.1 a client with one couldn't join a singleplayer world), and so do its default attribute modifications
  (PROVIDER-18).
- **Item storages in items** (a Fabric mod's bag, a NeoForge mod's pouch) cross to NeoForge's item handlers on 1.21.1,
  where they were unsupported.
- **The translation cache:** two launches sharing a game directory no longer delete each other's files (FC-6), and
  cleanup never follows a link (FC-7). A library module the platform lacks (LWJGL's NanoVG, Netty's HTTP codec) stays
  in the Fabric mod nesting it (PLAT-2).

## What changed on Forge 61 to 66

- **Held to NeoForge's bar**, with the refusals and the provider policy NeoForge had alone in v0.5.1: a Fabric API
  module another mod provides is that mod's, and Fabricated's own copy stands down.
- **The client with Fabric API is a gate**, with Fabric API's client modules: key mappings (native, KEYMAP-3), HUD
  elements on Forge's layers (HUD-2) and Fabric mods' own HUD hooks where Forge's layers call (HUD-4), screen events
  (SCREEN-1) and Mod Menu config screens.
- **Fabric's renderer API**, through Indigo on all four versions, with the throwing-model guard at Indigo's entry
  points; on Forge 61, Fabric models are drawn as moving blocks, with the overlay and as entities' blocks (FRAPI-8).
  Level-aware particle sprites work where Forge asks with model data (PART-4), and Forge 66's glow outline is a gate.
- **The difficult mods' Fabric builds load and are gated** (Sodium, Iris, Essential, malilib's set, Flashback).
- **Many corpus stops fixed:** Fabric mods' enum additions (Farmer's Delight), loot table names, registry events on
  Forge's registries, built-in packs enabled by default, Forge's compressed stack frames, a world asking to confirm
  experimental settings for a Fabric mod's data (PACK-5), and more (`CHANGELOG.md`, task 5).
- **Fabric API's effect events** name the command an effect comes from (EFFECT-1), and item storages in items cross to
  Forge's item handlers.

## What changed on Forge 47 (1.20.1)

- **Held to the same bar** as Forge 61 to 66, with the same refusals and provider policy.
- **Fabric models are drawn** in chunk sections, falling, moved by a piston, with the overlay, through Indigo
  (FRAPI-9); they were invisible before. Blocks drawn as entities keep vanilla's quads, as upstream on 1.20.1.
- **Forgified Fabric API runs beside Fabricated:** the server and the client with it are gates, and its modules'
  answers are its own (PROVIDER-13 to 16).
- **Fabric fuels and brewing recipes** (FUEL-1, BREW-1), `HudRenderCallback` and Fabric mods' HUD hooks at the HUD
  method's start and end (HUD-4), and Fabric mods' hooks into constructors through Fabricated's own injection point
  (CORPUS-103).
- **The difficult mods' Fabric builds load and are gated:** Sodium (with Indium), Iris (IRIS-1), Essential and
  malilib's set.
- **Corpus stops fixed:** Magna, Moonlight's codec, Porting Lib's drop capture and crafting size, MoreCulling, AppleSkin,
  Fabric API's custom ingredients and recipe conditions, and more (`CHANGELOG.md`, task 5).

## Upgrading from v0.5.1-alpha

- **Replace the jar.** Remove the old Fabricated jar (two Fabricated jars are refused) and Sinytra Connector.
- **The first launch is slower.** The cache from an older build is translated again, once, automatically: its schema
  is part of the cache key. Nothing in `.fabricated-cache` needs deleting.
- **`config/fabricated.json` keeps working.** Retired keys are accepted and ignored, and a file holding an earlier
  version's default limits, as it wrote them, reads as today's (nesting depth 8, LIMIT-2).
- **Sodium and Iris:** their Fabric builds now load by default, and a `loadUnsupported` entry for them is no longer
  needed. On NeoForge, prefer their NeoForge builds where they exist: the Fabric build of Sodium meshes NeoForge's
  fluids and models the Fabric way (`COMPATIBILITY.md` lists the gaps). Use one family, not a mix: Iris for NeoForge
  with Sodium's Fabric build, or the reverse, is refused, as neither can link to the other.
- **Essential:** the first launch downloads it and the next one loads it. Fabricated doesn't apply Essential's
  automatic updates; to update it, delete the jar the report names and launch twice.
- **On Forge 47 with Forgified Fabric API:** it now runs beside Fabricated, its modules used as they are.
- **Very large packs:** all the jars nested in a launch's mods may extract 8192 jars and 4 GiB in all (eight times one
  mod's limit, with the default `maxTotalUncompressedBytes`). A nested jar past it is rejected and the report names
  the limit; no pack we know comes near it.

## Known limits

- **Not every target is a gate yet.** These CI runs are informational, so this release doesn't promise them: the
  popular-mods corpora (on 1.21.1 the advanced corpus's client stays on Origins' screen, CORPUS-66, and a client with
  Xaero's World Map can hang as the test harness stops it, CORPUS-48: both the mods' own), Sodium Extra and Reese's
  Sodium Options on 26.3 (their builds there ask for a newer Sodium than CI tests), and OneConfig and PolyPlus on Forge
  (not tested). Every other target's run is a gate on each version it runs on, and held on two extended runs before
  this release.
- **What Forge lacks** is listed in *Unsupported on Forge* in `docs/FORGE.md` (on the `forge` branch) and
  `docs/FORGE-LEGACY.md` (on `forge-legacy`), such as some item API hooks and other mods' hooks inside the HUD method.
- **With Forgified Fabric API, its modules are used as they are.** What they do differently is theirs: its networking
  refuses a payload in the `minecraft` namespace (PROVIDER-5), and on 26.x its item API can stop the game asked an
  equipment slot set the Fabric way (PROVIDER-7).
- **OneConfig's keybinds** can't reach `KeyMapping.MAP`, which NeoForge retyped; OneConfig warns that its keybinds may
  shadow Minecraft's (KEYMAP-1).
- **Login queries** (`ServerLoginNetworking`, `ClientLoginNetworking`) aren't supported: NeoForge has no hook for that
  phase.
- **A Fabric mod whose initializer fails** after setting up a server configuration task can leave a singleplayer join
  waiting (ENTRY-1, not seen with a real mod).
- **Multiplayer:** CI tests dedicated servers and singleplayer clients, not a client joining a dedicated server.

Details for every item are in
[`docs/CHANGELOG.md`](https://github.com/cmdralph/Fabricated/blob/main/docs/CHANGELOG.md), every fixed finding in
[`docs/FINDINGS.md`](https://github.com/cmdralph/Fabricated/blob/main/docs/FINDINGS.md), and per-module status in
[`docs/COMPATIBILITY.md`](https://github.com/cmdralph/Fabricated/blob/main/docs/COMPATIBILITY.md).

## Installing

1. Install NeoForge or Forge for your exact Minecraft version.
2. Download the jar for that version:
   - NeoForge: `fabricated-0.6.0+mc<minecraft>.jar`.
   - Forge: `fabricated-forge-0.6.0+mc<minecraft>.jar` (1.21.11, 26.1.2, 26.2 and 26.3 on Forge 61 to 66; 1.20.1 on
     Forge 47).
3. Check the jar against `SHA256SUMS.txt`.
4. Put the jar in `mods`, next to your Fabric mods and the official Fabric API jar for that version (or Forgified
   Fabric API, whose modules Fabricated then uses). Remove Sinytra Connector, and any older Fabricated jar.

Fabricated never downloads anything and never modifies your mod jars. `logs/fabric-bridge-report.txt` says what loaded
and why anything didn't.

If you hit a crash, please open an issue and attach `logs/latest.log` and `logs/fabric-bridge-report.txt`.
